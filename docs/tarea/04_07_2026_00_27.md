# Registro de Actividad y Decisión Arquitectónica (ADR)

**Fecha:** 04-07-2026
**Sistema:** SIGTRAM3
**Área/Módulo:** Core / Arquitectura Frontend
**Estado:** Completado

---

## 1. Tarea o Acción Realizada
Implementación de un **Proxy Global (Interceptor)** para la validación automática de sesiones expiradas (HTTP 401) en todas las peticiones nativas asíncronas (`fetch()`).

---

## 2. Contexto y Problema Detectado
El sistema SIGTRAM3 realiza operaciones asíncronas utilizando la API moderna y nativa de Javascript: `fetch()`. Sin embargo, `fetch()` no posee un gestor de errores global (a diferencia de tecnologías legacy como jQuery con su `ajaxSetup`).

Cuando la sesión de Laravel expiraba por inactividad (ej. luego de 2 horas) y el usuario intentaba ejecutar una acción (guardar un formulario, abrir un modal), Laravel respondía correctamente con un código `401 Unauthorized`. Como no existía un control global, la pantalla ignoraba la respuesta o lanzaba errores silenciosos en la consola (F12), dejando la interfaz congelada y provocando una mala experiencia de usuario (UX).

Los desarrolladores se veían obligados a programar validaciones manuales (`if response.status === 401`) en cada una de las vistas, rompiendo el principio de diseño DRY (*Don't Repeat Yourself*).

---

## 3. Solución Implementada (Descripción Técnica)
Se implementó el patrón de diseño **Proxy / Interceptor** directamente sobre la API global `window.fetch`. Este código fue inyectado en el layout maestro (`resources/views/inicio.blade.php`), garantizando cobertura en todo el sistema.

### ¿Cómo funciona exactamente?
1. **Captura del Motor Original:** El script hace un respaldo de la función nativa de Javascript (`const { fetch: originalFetch } = window;`).
2. **Envoltura (Wrapper):** Se sobrescribe `window.fetch` con una función intermediaria. De ahora en adelante, cada vez que cualquier módulo llame a `fetch()`, pasará primero por este filtro.
3. **Manejo del Error 401:** 
   - El Proxy ejecuta la petición real. Si el servidor responde con un código distinto a `401`, la deja pasar limpiamente al módulo que la solicitó.
   - Si detecta un **401 (Sesión Expirada)**, el Proxy secuestra el flujo:
     - Dispara inmediatamente una notificación visual estándar del sistema (`AppNotif.error`) alertando de la inactividad.
     - Programa una expulsión forzosa (redirección a `/login`) a los 2 segundos.
     - **Técnica de Aislamiento:** Retorna una Promesa bloqueada (`return new Promise(() => {});`). Esta técnica avanzada evita que la función original intente seguir ejecutándose o procesar un JSON que no existe, previniendo que la consola del navegador se llene de excepciones innecesarias.

---

## 4. Impacto y Beneficios Corporativos
* **Escalabilidad:** Los desarrolladores actuales y futuros del equipo ya no necesitan preocuparse por validar sesiones expiradas en sus módulos. Pueden programar `fetch()` sabiendo que la seguridad perimetral ya está cubierta de fondo.
* **Seguridad:** Cumplimiento con el estándar UX de seguridad; se elimina la posibilidad de que datos residuales en pantalla queden interactuables tras un cierre de sesión.
* **Mantenibilidad:** Toda la lógica de expulsión reside en un solo lugar (punto único de falla/edición).
